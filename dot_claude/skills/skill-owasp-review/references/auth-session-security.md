# Authentication & Session Security

## Password Storage

### Requirements
- Use **Argon2id** (preferred), **bcrypt** (cost >= 12), or **PBKDF2** (>= 600k iterations with SHA-256)
- Never MD5, SHA-1, SHA-256, or any unsalted hash
- Salt is auto-generated by bcrypt/Argon2id — don't roll your own

### Vulnerable

```javascript
// MD5 — brute-forceable in seconds
const hash = crypto.createHash('md5').update(password).digest('hex');

// SHA-256 unsalted — rainbow table vulnerable
const hash = crypto.createHash('sha256').update(password).digest('hex');
```

### Secure

```javascript
const bcrypt = require('bcrypt');
const hash = await bcrypt.hash(password, 12);
const valid = await bcrypt.compare(input, hash);
```

```python
# Argon2id
from argon2 import PasswordHasher
ph = PasswordHasher()
hash = ph.hash(password)
ph.verify(hash, input_password)
```

## Session Management

### Secure session configuration

```javascript
app.use(session({
  secret: process.env.SESSION_SECRET,  // From environment, not hardcoded
  name: '__Host-sid',                  // __Host- prefix: Secure + Path=/ + no Domain
  cookie: {
    secure: true,                      // HTTPS only
    httpOnly: true,                    // No JS access
    sameSite: 'lax',                   // CSRF protection
    maxAge: 8 * 60 * 60 * 1000,       // 8h absolute timeout
  },
  resave: false,
  saveUninitialized: false,
}));
```

### Critical requirements

1. **Session ID entropy >= 128 bits** — use framework defaults, don't generate your own
2. **Regenerate on login** — prevent session fixation:
   ```javascript
   req.session.regenerate((err) => {
     req.session.userId = user.id;
     req.session.save(() => res.json({ success: true }));
   });
   ```
3. **Invalidate on logout** — destroy server-side, not just clear cookie:
   ```javascript
   req.session.destroy((err) => {
     res.clearCookie('__Host-sid');
     res.json({ success: true });
   });
   ```
4. **Absolute timeout** (e.g., 8h) AND **idle timeout** (e.g., 30min)
5. **Cookie flags**: `Secure`, `HttpOnly`, `SameSite=Lax` minimum

### What to flag
- `session.regenerate()` missing after authentication
- `session.destroy()` missing on logout
- Session ID in URL parameters
- Missing `Secure` or `HttpOnly` cookie flags
- No absolute session timeout

## JWT Security

### Common mistakes

| Mistake | Risk | Fix |
|---------|------|-----|
| Skipping signature verification | Token forgery | Always verify with `algorithms` allowlist |
| `alg: "none"` accepted | Complete bypass | Explicitly specify allowed algorithms |
| Secret in source code | Token forging | Use env var or KMS for secret |
| Token in localStorage | XSS exfiltration | Use httpOnly cookie |
| Missing `exp` claim | Infinite session | Always set expiration |
| Missing `aud` validation | Cross-service token misuse | Validate audience matches your service |
| Symmetric signing for multi-service | Secret sharing | Use asymmetric (RS256/ES256) for multi-service |

### Secure JWT verification

```javascript
const jwt = require('jsonwebtoken');
const decoded = jwt.verify(token, publicKey, {
  algorithms: ['RS256'],        // Explicit allowlist — blocks "none" and HS256
  audience: 'my-api',           // Validates aud claim
  issuer: 'auth.example.com',   // Validates iss claim
  clockTolerance: 30,           // 30s tolerance for clock skew
});
```

## OAuth 2.0 / OIDC

### Pitfalls and fixes

| Pitfall | Risk | Fix |
|---------|------|-----|
| Implicit flow for SPAs | Token in URL fragment, history, logs | Authorization Code + PKCE |
| Missing `state` parameter | CSRF on OAuth flow | Use random `state`, verify on callback |
| No PKCE | Auth code interception | Always use PKCE (S256 challenge method) |
| Overly broad scopes | Violates least privilege | Request minimal scopes |
| Redirect URI with wildcards | Auth code theft | Exact-match redirect URIs only |
| No refresh token rotation | Stolen token reuse | Rotate on each use, detect reuse |
| Tokens in localStorage | XSS exfiltration | BFF pattern or httpOnly cookies |

### Secure OAuth flow (Authorization Code + PKCE)

```javascript
// 1. Generate PKCE verifier + challenge
const verifier = crypto.randomBytes(32).toString('base64url');
const challenge = crypto.createHash('sha256').update(verifier).digest('base64url');

// 2. Authorization request
const authUrl = `https://auth.example.com/authorize?` +
  `response_type=code&client_id=${clientId}&redirect_uri=${redirectUri}` +
  `&scope=openid%20profile&state=${state}&code_challenge=${challenge}` +
  `&code_challenge_method=S256`;

// 3. Token exchange (server-side)
const tokenResponse = await fetch('https://auth.example.com/token', {
  method: 'POST',
  body: new URLSearchParams({
    grant_type: 'authorization_code',
    code: authorizationCode,
    redirect_uri: redirectUri,
    client_id: clientId,
    code_verifier: verifier,  // PKCE verifier
  }),
});
```

## Authorization Patterns

### RBAC (Role-Based Access Control)

```javascript
// Middleware pattern
function requireRole(...roles) {
  return (req, res, next) => {
    if (!req.user || !roles.includes(req.user.role)) {
      return res.status(403).json({ error: 'Forbidden' });
    }
    next();
  };
}

app.delete('/api/users/:id', requireAuth, requireRole('admin'), deleteUser);
```

### Ownership verification (IDOR prevention)

```javascript
app.get('/api/documents/:id', requireAuth, async (req, res) => {
  const doc = await db.documents.findById(req.params.id);
  if (!doc) return res.status(404).json({ error: 'Not found' });

  // Ownership check
  if (doc.ownerId !== req.user.id && req.user.role !== 'admin') {
    return res.status(403).json({ error: 'Forbidden' });
  }

  res.json(doc);
});
```

### What to flag
- Endpoints with `findById(req.params.id)` without ownership/role check
- Admin routes without role middleware
- Authorization logic only in frontend
- Default-allow access patterns
- Missing authorization on DELETE/PUT/PATCH endpoints

## Rate Limiting

### Login endpoint

```javascript
const rateLimit = require('express-rate-limit');
const loginLimiter = rateLimit({
  windowMs: 15 * 60 * 1000,  // 15 minutes
  max: 10,                    // 10 attempts per window
  keyGenerator: (req) => req.body.email || req.ip,
  message: { error: 'Too many login attempts, try again later' },
  standardHeaders: true,
});

app.post('/login', loginLimiter, loginHandler);
```

### What to flag
- Login endpoint without rate limiting
- OTP/password reset without rate limiting
- API endpoints without any rate limiting
- Rate limiting only by IP (easy to bypass with rotating proxies) — combine with account identifier

## Account Security

### Login response — prevent user enumeration

```javascript
// VULNERABLE — leaks whether email exists
if (!user) return res.status(404).json({ error: 'User not found' });
if (!validPassword) return res.status(401).json({ error: 'Wrong password' });

// SECURE — generic message for both cases
if (!user || !await bcrypt.compare(password, user.passwordHash)) {
  return res.status(401).json({ error: 'Invalid credentials' });
}
```

### Account lockout

```javascript
// After N failed attempts, lock account temporarily
if (user.failedAttempts >= 5) {
  if (Date.now() - user.lastFailedAt < 30 * 60 * 1000) {  // 30 min lockout
    return res.status(423).json({ error: 'Account temporarily locked' });
  }
  user.failedAttempts = 0;  // Reset after lockout period
}
```

### Re-authentication for sensitive operations
- Password change
- Email change
- Payment/financial operations
- API key generation
- MFA enrollment/removal
- Account deletion
